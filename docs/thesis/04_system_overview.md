# 第4章 系统总体设计

## 4.1 系统需求分析
系统需在桌面环境下运行，支持用户通过鼠标、键盘操作构建迷宫、放置权重节点并选择算法。为了兼顾教学需求，界面必须提供中文提示、图例说明与状态反馈，并允许动态调整动画速度与生成策略。

## 4.2 总体架构
项目采用模块化设计，主要由以下子系统组成：

- **界面布局模块（`src/ui/layout.py`）**：构建顶部工具栏、选择摘要行、状态栏与图例区域，负责控件排列和主题样式。
- **控件组件模块（`src/widgets.py`）**：实现按钮、下拉菜单、标签与图例单元等通用组件，封装交互逻辑与绘制函数。
- **动画模块（`src/animations.py`）**：对节点访问与最短路径回溯过程进行队列式调度，支持暂停、恢复与清空操作。
- **迷宫与算法模块（`src/maze.py`、`src/menu_config.py`）**：定义网格节点、权重处理、迷宫生成器与算法元数据。
- **主控模块（`src/main.py`）**：整合事件循环、状态管理、绘制流程与算法执行入口，是系统运行的核心。

整体架构遵循 Model-View-Controller 思路：迷宫状态与算法计算属于模型层，PyGame 绘制与控件展示构成视图层，事件循环与状态同步则相当于控制器层。

## 4.3 数据流与状态管理
应用在 `src/state.py` 中定义全局状态对象，包含当前算法、迷宫生成策略、比较模式、动画速度、状态文本等字段。UI 控件通过回调更新状态，主循环根据状态驱动算法执行与动画播放。为了避免界面残影或状态覆盖，系统在每帧重置图例与标签位置，并通过 `set_status` 函数集中管理状态显示。

## 4.4 用户交互流程
1. 用户通过下拉菜单选择算法、速度、比较模式及迷宫生成策略；
2. 在网格上拖拽放置障碍、权重或起终点节点；
3. 点击“开始可视化”触发算法执行，动画模块按照节点访问顺序渲染；
4. 使用“暂停动画”或“重新开始”进行控制，状态栏实时反馈当前阶段；
5. 完成后，可通过重置或更换算法继续实验。

## 4.5 本章小结
本章介绍了系统需求、总体架构与交互流程，为后续章节深入分析算法实现和界面呈现打下基础。
