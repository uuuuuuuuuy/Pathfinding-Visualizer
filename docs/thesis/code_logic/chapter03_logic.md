# 第3章配套代码逻辑说明

本说明聚焦论文第3章“方案设计”中涉及的核心代码结构，以抽象视角总结模块职责与数据流转，帮助在正文中引用时具备清晰的技术依据。

## 1. 界面布局与控件组织
- **布局调度**：`src/ui/layout.py` 暴露 `build_header` 与 `build_legend` 等构造函数，按照预设的像素常量将下拉菜单、全局按钮、摘要行与图例分段放置。每次绘制帧都会调用这些函数返回的控件集合，保证窗口尺寸变化时控件自动重新排布。
- **控件抽象**：`src/widgets.py` 定义 `Button`、`Dropdown`、`Label` 等类，分别封装点击、展开、文本测量等行为。布局模块不直接关心绘制细节，而是通过组合这些控件来完成界面结构。

## 2. 状态管理与数据驱动
- **全局状态容器**：`src/state.py` 中的 `GlobalState` 记录当前算法、迷宫生成策略、比较模式、动画速度、状态文本等字段。论文第3章描述的“摘要行”和“状态栏”正是读取该状态对象实时渲染。
- **菜单配置**：`src/menu_config.py` 使用 `AlgorithmDefinition`、`MazeGeneratorDefinition` 等数据类集中声明可选项。每个定义包含显示名称、内部标识、适配条件与描述文本，使 UI 渲染与算法执行完全数据驱动。

## 3. 数据流与事件传播
- **输入响应**：主循环 `src/main.py` 在事件分发阶段将鼠标、键盘事件传递给控件实例。控件触发的回调函数会更新 `GlobalState` 或调用动画/迷宫模块，构成从用户输入到内部状态的第一条数据流。
- **状态回读**：更新后的状态在随后的绘制阶段由布局模块读取，通过 `Label` 等控件呈现当前选择、提示信息与按钮高亮，形成第二条自上而下的数据流。

## 4. 颜色与字体策略
- **主题常量**：`src/constants.py` 集中维护颜色、间距、字号等界面参数。论文中提到的“按钮配色”“状态栏高度”均来源于此，便于统一修改。
- **字体加载**：`src/fonts.py` 提供 `resolve_font_pair` 与 `load_font` 辅助函数，自动扫描 `assets/fonts/` 目录中可用的中文字体并缓存结果，确保布局模块调用时获得符合本地化需求的字体对象。

## 5. 迷宫网格与节点模型
- **网格结构**：`src/maze.py` 声明 `Node` 与 `Grid` 类，分别描述单个格子与整张网格的属性。节点类型（墙体、权重、起终点等）通过枚举或布尔标记区分，为图例与交互提供统一的数据基础。
- **绘制对接**：`Grid.draw` 方法按节点状态决定颜色与填充方式，与论文中“节点类型图例”一致，为上层布局提供可靠的展示支撑。

## 6. 控制按钮与操作流程
- **全局控制器**：`src/ui/layout.py` 中的 `build_control_buttons` 函数负责创建“开始可视化”“暂停动画”“重新开始”等按钮，并把对应回调绑定到动画调度器和状态管理函数。
- **交互链路**：按钮点击后触发 `main.py` 中的 `start_visualization`、`pause_animation`、`reset_board` 等辅助函数，进一步调用动画模块或迷宫重置逻辑，实现论文第3章图示的交互流程。

## 7. 章节总结映射
综上，论文第3章所述的需求分析、设计原则与架构拆分在代码中分别对应：
- 通过模块划分实现“模块化与解耦”；
- 借助中文字体与颜色常量落实“以用户为中心”；
- 依赖 `set_status` 与摘要行控件达成“实时反馈”；
- 以数据驱动的菜单定义保证“可扩展性”。
这些逻辑支撑了方案层面的论述，确保文档与实现保持一致。
