# 第5章 实验设计与结果分析

## 5.1 实验目标
实验旨在评估不同路径规划算法在相同迷宫配置下的性能差异，并观察界面交互功能对学习体验的影响。重点比较路径长度、访问节点数量、执行效率以及用户在操作过程中的反馈。

## 5.2 实验环境
- 操作系统：Windows 11 / Ubuntu 22.04
- Python 版本：3.10 及以上
- 依赖库：Pygame 2.6.1
- 硬件配置：8GB 内存及以上，确保动画播放流畅

## 5.3 评估指标
项目内置的结果弹窗会直接给出以下度量：

1. **访问节点数**：由 `explored_length` 统计搜索过程中被弹出的节点数量，用于衡量状态空间的覆盖范围；
2. **最短路径长度**：`path_length` 字段表示最短路径的步数，验证算法的最优性；
3. **路径成本与计算耗时**：`path_cost` 和 `time` 分别记录最短路径的累计权重以及求解阶段的 CPU 耗时，可用于评估不同算法在带权场景下的效率表现。

此外，动画播放时长与交互操作次数目前尚未在代码层面自动采集，需要结合速度设置和日志手动记录，例如通过屏幕录制或实验观察表格补充对应数据。

## 5.4 实验流程
1. 构建统一的迷宫与起终点配置，分别运行各类算法并记录结果；
2. 调整动画速度，观察节点着色顺序与运行时长的变化；
3. 启用比较模式，比较多种算法在同一场景下的路径差异；
4. 使用暂停与重新开始功能，在关键节点截取状态信息或截图；
5. 收集用户主观评价，评估界面布局、状态提示与图例说明的有效性。

## 5.5 案例分析
- **复杂迷宫场景**：结合递归分割生成的迷宫与权重节点，可对比 Dijkstra 与 A* 在带权图中的表现差异；
- **稀疏障碍场景**：重点观察 BFS 与双向 BFS 在开放空间中的速度优势；
- **高权重区域**：利用数字键设置 5-9 的权值，验证算法对成本累积的敏感度。

## 5.6 数据记录与可视化
实验数据可通过日志、截图或导出 CSV 的方式保存。结合状态栏文本可构建时间轴，描述算法执行阶段与用户交互行为，为论文撰写提供可追溯的证据链。

## 5.7 本章小结
本章给出了系统化的实验设计与分析框架，确保性能评估与用户体验调研具备可重复性，为最终的总结与未来展望提供数据支撑。
