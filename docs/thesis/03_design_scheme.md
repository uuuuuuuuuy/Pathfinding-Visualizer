# 第3章 方案设计

## 3.1 系统需求分析
系统需要在桌面环境下平稳运行，允许用户通过鼠标拖拽或键盘快捷键构建迷宫、放置权重节点，并从多个路径规划算法中进行选择。为满足教学与研究需求，界面必须提供中文提示、清晰的图例说明、实时状态反馈，同时支持动画速度、比较模式与迷宫生成策略的自由切换。系统还需在不同分辨率下保持布局稳定，避免控件重叠或遮挡迷宫网格。

## 3.2 设计原则
方案设计遵循以下原则：

- **模块化与解耦**：核心逻辑拆分为状态管理、算法执行、动画调度、界面布局等模块，便于单独维护与扩展；
- **以用户为中心**：通过中文本地化、色彩区分与图例提示降低学习成本，关键操作按钮采用醒目配色；
- **实时反馈**：状态栏与摘要行随操作更新，迷宫生成与算法可视化过程中及时显示当前阶段和结果；
- **可扩展性**：算法、迷宫生成器和字体加载均采用数据驱动设计，新增配置时无需重构现有界面。

## 3.3 总体架构
项目采用类似 Model-View-Controller 的分层结构：

- **界面布局模块（`src/ui/layout.py`）** 构建顶部工具栏、摘要行、状态标签与图例区域，并负责控件的动态排布；
- **控件组件模块（`src/widgets.py`）** 提供按钮、下拉菜单、标签与图例单元的绘制与交互封装；
- **动画模块（`src/animations.py`）** 管理节点访问序列、最短路径回溯，以及暂停、恢复、清空等控制；
- **迷宫与算法模块（`src/maze.py`、`src/menu_config.py`）** 定义网格节点模型、迷宫生成算法以及可供选择的路径规划策略；
- **主控模块（`src/main.py`）** 负责事件循环、状态同步与绘制调度，协调用户输入与系统输出。

## 3.4 数据流与状态管理
`src/state.py` 中的全局状态对象记录当前算法、迷宫生成策略、比较模式、动画速度、状态文本等信息。用户操作触发控件回调更新状态，主循环据此驱动算法执行与动画播放。为避免界面残影，系统在每帧重置图例、标签的绘制区域，并通过 `set_status` 函数集中维护状态文本，确保提示信息准确覆盖。

## 3.5 用户交互流程
1. 用户通过下拉菜单选择算法、速度、比较模式与迷宫生成策略；
2. 在网格上放置或拖拽起点、终点、障碍和权重节点，配置实验场景；
3. 点击“开始可视化”启动算法执行，动画模块按访问顺序渲染节点变化；
4. 利用“暂停动画”与“重新开始”控制播放节奏，并根据状态提示观察当前阶段；
5. 运行完成后可保存截图、调整参数或切换算法，继续新的实验。

## 3.6 本章小结
本章从需求、原则、架构、数据流与交互流程等方面阐述了系统的整体方案设计，为下一章深入分析算法与界面实现奠定基础。
